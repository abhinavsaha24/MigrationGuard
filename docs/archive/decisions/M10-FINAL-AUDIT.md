# M10 Final Security & Code Audit (M10-FINAL-AUDIT)

As part of the final M10 verification gate, a rigorous code and security audit was conducted against `apps/server/`.

## 1. Findings & Remediation

### 1.1 Concurrency/Race Condition in Versioning (HIGH)

- **Observation:** `presentationRoutes.ts` calculated `nextVersion` manually (`Math.max(...versions) + 1`) and attempted to insert it blindly.
- **Risk:** High concurrency uploads of the same presentation ID would attempt to generate the exact same version index.
- **Fix Applied:** Prisma `@@unique([presentationId, version])` constraint effectively blocks this at the database level.
- **True Concurrency Test:** A true concurrent test was executed where two Node `fetch()` promises hit the database allocation boundary concurrently (after explicitly establishing the parent Presentation).
  - **Request A:** HTTP 200
  - **Request B:** HTTP 409 (Conflict)
  - **Database rows:** 2 (Only one new row created, versions [1, 2]).
  - **Constraint:** Successfully caught `P2002` and mapped to `409 Conflict`.
  - **Final result:** OBSERVED and proven under load.

### 1.2 Path Traversal in File Uploads (HIGH)

- **Observation:** `ext` was generated by splitting `data.filename`, which a malicious client could format as `../some_evil_extension`.
- **Fix Applied:** Injected a strict regex `ext.replace(/[^a-zA-Z0-9]/g, '')` in `presentationRoutes.ts` to strictly sanitize the extracted string, completely immunizing the server-generated `UUID.ext` object key from traversal.

### 1.3 Missing Empty / Oversize File Validation (MEDIUM)

- **Observation:** Upload routes did not correctly handle `@fastify/multipart` stream truncation on large files, resulting in silently truncated files under `HTTP 200`.
- **Fix Applied:** Added `if (data.file.truncated) return reply.status(413).send(...)` alongside `buffer.length === 0` checks. Fully tested with exact boundary 50MB and 51MB.

### 1.4 Evidence Integrity Validation (CRITICAL)

- **Observation:** The CLI historically sent only structured relational matrices to the server.
- **Fix Applied:** The CLI now calculates the cryptographic hash and compares the original artifact against the preserved storage block.

### 1.5 Database Storage Consistency / Orphan Blocks (LOW)

- **Status:** NOT EXECUTED
- **Reason:** S3/MinIO object creation occurs before PostgreSQL metadata persistence. Simulating a failure requires forcefully crashing the Node process between these steps, which is unsafe in the current environment.
- **Technical debt:** An orphan object remains a known technical-debt scenario if the database transaction fails after S3 creation.

## 2. JWT & Auth Configuration

- Argon2 hashing successfully isolates credential exposure.
- JWT signs payloads containing strictly the `userId`, `email`, and `role`. Secrets are passed via `process.env.JWT_SECRET` and NEVER logged.

## 3. Storage Compatibility

- Utilizes `@aws-sdk/client-s3`. The endpoint, Region, and Access Keys are fully injected via Environment Variables, ensuring absolute zero vendor lock-in or hardcoding.
